# تدفق الألوان والمخزون داخل المنتج

## القاعدة الأساسية

تحليل اللون هو **اقتراح قابل للمراجعة** فقط. لا ينشئ لونًا أو متغيرًا أو كمية ولا يغيّر حالة المنتج. يعتمد الموظف الاقتراح أو يعدل اسمه أو يتجاهله، ثم يدخل المخزون بنفسه في خطوة مستقلة.

| الخطوة | ما يقوم به النظام | ما يبقى بيد الموظف |
|---|---|---|
| تحليل الألوان | يقرأ صور WebP التشغيلية ويقترح أسماء ألوان عربية مع ثقة وصور مرتبطة | اعتماد الاقتراح أو تغيير الاسم أو تجاهله |
| اعتماد لون | ينشئ متغيرًا واحدًا لكل لون بلا قياسات، أو متغيرًا لكل تركيبة لون وقياس | اختيار اللون والصور المرتبطة به |
| إضافة لون يدوي | ينشئ المتغيرات اللازمة بالكمية صفر | إدخال اسم اللون عند عدم وجود اقتراح مناسب |
| ربط صورة بلون | يربط الصورة بأول متغير للون ويجعلها مؤكدة اللون | مراجعة صحة الرابط |
| حفظ المخزون | يحدّث كمية كل متغير ويحسب الحالة التشغيلية | إدخال العدد الفعلي لكل لون أو لون/قياس |

## إدخال الكمية

إذا لم يكن للمنتج قياسات، تظهر بطاقة كمية واحدة لكل لون. إذا كانت القياسات موجودة، تظهر مصفوفة: الصفوف ألوان والأعمدة قياسات، ولكل خلية كمية مستقلة. لا يقبل الحفظ كمية سالبة أو إدخالًا ناقصًا لمتغير قائم.

## الحماية

1. لا تحلل المنصة أو تعتمد اللون تلقائيًا من دون مراجعة الموظف.
2. لا تغيّر أي عملية لون أو مخزون حالة المنتج إلى `active`، ويظل المنتج المسودة خارج `products.publicList`.
3. تسجل إضافة اللون وربط الصورة وحفظ المخزون في سجل عمليات المنتج الموحد، مع مصدر `products_ui`، لتستخدم قناة WhatsApp نفس قواعد التحقق لاحقًا.
4. لا تكتب هذه العمليات إلى OneDrive ولا تعدل الأصل عالي الجودة.

## حالات قائمة العمل

تظهر القائمة كل المنتجات افتراضيًا، ثم تسمح بالتصفية المستقلة إلى: **مسودات** (حالة النشر `draft`)، و**يحتاج إكمالًا** (وجود حقول ناقصة)، و**يحتاج مراجعة** (حالة العمل `needs_review` أو `ready`)، و**نشط** (حالة نشر مستقبلية `active`). لا تعني حالة «يحتاج إكمالًا» أو «يحتاج مراجعة» نشر المنتج؛ إنها وصف لعمل الموظف فقط.

لا تنفذ المنصة في هذه المرحلة انتقالًا من `draft` إلى `active`. تبقى كل المنتجات الحالية مسودات، ويظهر تبويب «نشط» للتمييز المستقبلي فقط ولا يقدم زر تفعيل أو انتقال ضمن الواجهة.
