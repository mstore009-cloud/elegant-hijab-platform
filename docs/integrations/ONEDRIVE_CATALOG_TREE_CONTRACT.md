# عقد شجرة كتالوج OneDrive

## المبدأ المعتمد

تكون شجرة OneDrive هي **مصدر تنظيم الكتالوج**. لا يُطلب من الموظف اختيار مجموعة يدوية لكل منتج إذا كانت بنية المجلدات تحددها بوضوح. تحتفظ المنصة بنسخة بيانات منظمة للتشغيل والبحث والمخزون، لكنها تستورد المجموعة والمنتج والوسائط من موقعها في الشجرة.

## البنية المقترحة

```text
Catalog/
├─ Hijabs/                         ← المجموعة
│  ├─ HJB-001/                     ← المنتج؛ الاسم هو كوده الرسمي
│  │  ├─ 01.jpg                    ← صور مختلطة، ولا يلزم اسم اللون
│  │  ├─ 02.jpg
│  │  ├─ 03.jpg
│  │  └─ 04.jpg
│  └─ HJB-002/
├─ Shawls/
│  └─ SHL-001/
└─ Ties/
   └─ TIE-001/
```

## قواعد التحويل إلى بيانات تشغيلية

| موقع العنصر في الشجرة | ما تنشئه المنصة |
|---|---|
| المجلد الأول تحت `Catalog` | مجموعة المنتج، مثل Hijabs أو Shawls أو Ties. |
| المجلد الثاني | منتج أب، واسم المجلد هو كود المنتج الرسمي؛ لا يُدخل يدويًا ولا ينشئ النظام بديلًا له. |
| الصور والفيديوهات داخل مجلد المنتج | مجموعة وسائط مختلطة يعالجها النظام داخل المنتج نفسه فقط، لا عبر كتالوج كامل. |
| نتيجة التحليل | يجمع النظام صور الزوايا المتعددة للون نفسه تحت متغير لون واحد، ثم يعرض الصور والاسم المتوقع للمراجعة. |
| ملف بيانات اختياري | يضيف الاسم وسعر البيع والوصف عند توفره؛ غيابه لا يغير كود المنتج أو مجموعته، لكنه قد يبقي السجل في مسودة. |

## ضوابط الاستيراد

لا يعتبر المجلد منتجًا جاهزًا للنشر لمجرد وجوده. ينشأ كسجل **مسودة** إذا غاب سعر البيع أو صورة أساسية أو كمية المخزون. لا يعد غياب اسم اللون في الملفات نقصًا؛ فالصور مختلطة أصلًا ويجري تحليلها داخل مجلد المنتج ذي الكود المعروف. تحفظ المنصة معرفات المجلدات والملفات الأصلية لتعرف مصدر كل سجل، وتسمح بتصحيح النقص من الداخل دون فقدان صلة المصدر.

## المجموعات الجديدة وتغييرات الشجرة

يقرأ النظام المجلدات المباشرة تحت جذر الكتالوج باعتبارها مجموعات منتجات. إذا ظهر مجلد جديد مثل `مكملات حجاب`، ينشئ النظام مجموعة مقابلة داخل المنصة بحالة **بانتظار مراجعة**، ثم يكتشف مجلدات المنتجات الموجودة تحته بالطريقة نفسها. لا يظهر القسم الجديد في المتجر أو أمام العميل قبل أن يعتمد المدير اسمه وترتيبه وظهوره.

| التغيير في OneDrive | السلوك داخل المنصة |
|---|---|
| إنشاء مجلد مجموعة جديد | إنشاء مجموعة مكتشفة بانتظار مراجعة، وإرسال إشعار للموظف؛ لا تظهر للعميل قبل الاعتماد. |
| إعادة تسمية مجموعة | إنشاء إشعار اقتراح تحديث؛ يعتمد الموظف الاسم أو يرفضه، بالاعتماد على معرف المجلد الخارجي نفسه لمنع التكرار. |
| نقل مجلد منتج إلى مجموعة أخرى | إنشاء إشعار يوضح المصدر والوجهة؛ لا يتغير الارتباط إلا بعد قبول الموظف، ولا ينشأ منتج مكرر. |
| اختفاء أو حذف مجلد منتج | إشعار «مصدر مفقود» ووضع المنتج بانتظار مراجعة؛ لا يحذف السجل أو الطلبات أو المخزون تلقائيًا. |
| حذف مجموعة كاملة | إيقاف مزامنتها وإشعار الموظف؛ لا يتم حذف السجل التشغيلي آليًا. |

يحمل إشعار المراجعة نوع التغيير، والمسار السابق والجديد عند وجودهما، ومعرف المجلد الخارجي، والمنتجات المتأثرة، وثلاثة إجراءات واضحة للموظف: **اعتماد**، أو **رفض مع إبقاء بيانات المنصة كما هي**، أو **تحويل إلى المدير**. لا تطبق أي عملية لا رجعة فيها من مزامنة الملفات وحدها.

## قاعدة الصور المختلطة والألوان المعتمدة

1. يحدد النظام المجموعة والكود من مسار المجلد أولًا، ثم يحلل فقط صور هذا المنتج؛ فلا يقارن صورة بمكتبة كل المنتجات.
2. يجمّع صور الزوايا المختلفة للون نفسه، ثم يقدّم لكل لون صورة أو أكثر واسمًا متوقعًا.
3. عند الثقة العالية، يستطيع الموظف اعتماد الجميع دفعة واحدة. وعند الثقة المنخفضة، يعرض النظام قائمة ألوان أو يطلب اختيارًا للعنصر الغامض فقط.
4. لا يعيد الموظف كتابة كل الألوان إذا كان معظم التحليل صحيحًا؛ يصحح اللون الخاطئ أو يضيف اللون الناقص فقط.
5. بعد اعتماد الألوان، يطلب النظام كمية كل لون، مع خيار كمية موحدة للجميع أو كميات مختلفة. لكل لون، أو تركيبة لون وقياس عند وجود القياس، مخزون مستقل.

## قالب البيانات الوصفية داخل مجلد المنتج

يوضع ملف نصي منظم، ويفضل باسم `product.txt`، داخل كل مجلد منتج. يمكن قبول Word عند الضرورة، لكن TXT ذي حقول ثابتة هو المسار الأكثر موثوقية للقراءة الآلية. الملف لا يكرر المجموعة أو الكود أو الألوان أو المخزون؛ فهذه تأتي من الشجرة والتحليل والمراجعة التشغيلية.

| الحقل | الحالة | السبب |
|---|---|---|
| `PRODUCT_NAME_AR` | إلزامي | الاسم المعروض في المتجر والبطاقات والرسائل. |
| `SELLING_PRICE_IQD` | إلزامي | سعر البيع المعتمد للطلب والنشر. |
| `DESCRIPTION_AR` | إلزامي | وصف العميل والمتجر؛ لا يعتمد على تخمين الصورة وحدها. |
| `SIZES` | اختياري | قائمة منظمة مثل `M, L, XL, XXL`؛ تطبق افتراضيًا على كل الألوان عند إنشاء المنتج. |
| `PREVIOUS_PRICE_IQD` | اختياري | يستخدم فقط في عرض حقيقي معتمد؛ عند فراغه لا يظهر سعر سابق أو خصم للمنتج. |
| `PRODUCT_STATUS` | اختياري | يحدد إن كان السجل يبدأ مسودة أو جاهزًا للمراجعة؛ الأصل مسودة. |

القالب المقترح محفوظ في `PRODUCT_METADATA_TEMPLATE.txt`.

لا تُسجل `PATTERN` أو تعليمات العناية أو ملاحظة الحملة داخل هذا القالب. النقشة مرئية للعميل في الصور، وتعليمات العناية ليست جزءًا مطلوبًا من التدفق الحالي، بينما تدار الحملات والعروض من قسم التسويق لا من ملف كل منتج.

عند وجود عرض، يكون `SELLING_PRICE_IQD` هو السعر الحالي الذي يدفعه العميل، ويكون `PREVIOUS_PRICE_IQD` هو السعر القديم الحقيقي الظاهر للمقارنة. مثال: `SELLING_PRICE_IQD: 12000` و`PREVIOUS_PRICE_IQD: 15000`. لا يجوز توليد سعر سابق أو نسبة خصم من دون قيمة سابقة حقيقية معتمدة.

عند وجود `SIZES`، ينشئ النظام بعد اعتماد الألوان كل تركيبة لون وقياس مبدئيًا؛ فلا يكرر الموظف قائمة القياسات تحت كل لون. بعد ذلك يبقى المخزون مستقلًا: نفاد `Beige + M` لا يغير حالة `Beige + L` أو `Black + M`.

## ما لا يغنيه OneDrive

تظل الصلاحيات والمخزون والطلب والعميل والبيانات المالية داخل المنصة. شجرة OneDrive تختصر تصنيف الكتالوج والوسائط، لكنها لا تستبدل سجل المنتج التشغيلي أو قواعد إخفاء التكلفة والهامش.

## حالة الموصل

الموصل المباشر ما زال مؤجلًا بعد فشل خدمة App Folder المحدودة في الاختبار الحي. العقد الحالي صالح مهما كانت آلية النقل لاحقًا: موصل Microsoft Graph، استيراد مجلد مجمّع، أو رفع داخلي يحافظ على البنية نفسها.
