## بوابات إلزامية قبل كل فرع

| البوابة | الشرط |
|---|---|
| المواصفة | أن تكون أهداف الفرع وحدوده وقواعده وحالات الخطأ مكتوبة ومعتمدة. |
| القرار | أن تكون البدائل والقيد الخارجي وأثر التغيير موثقين. |
| الأمان | أن تكون البيانات الحساسة والصلاحيات ومسارات الفشل محددة. |
| القبول | أن توجد حالات قبول للمسار الطبيعي والاستثنائي وقابلية التراجع. |

## ترتيب البناء الحالي

1. الهوية والصلاحيات الحبيبية وحماية البيانات المالية.
2. المنتجات والمتغيرات والمخزون.
3. موصل OneDrive واختبار الجدوى ومسار الإدخال البديل.
4. الطلبات والـ Inbox والـ CRM.
5. البوتات والتكاملات والنشر والتحليلات والتسويق والولاء.

## قيود لا يجوز تجاوزها

| القيد | تطبيقه في النظام |
|---|---|
| بيانات التكلفة | لا تعود من الواجهة الخلفية ولا تظهر في الواجهة لغير صاحب صلاحية مالية حساسة. |
| التوصيل | يبدأ يدويًا؛ لا تعتمد حالات تلقائية قبل نجاح ربط شركة التوصيل. |
| الخصومات | لا تنشئ قواعد خصم فردي آلية تضعف قيمة العلامة. |
| OneDrive | لا يُربط بالنواة مباشرة؛ يبقى خلف موصل مستقل مع بديل آمن. |
| محتوى المنتج | لا يُستخدم أي تعديل أو توليد يغيّر اللون أو الخامة أو النقشة الحقيقية. |
